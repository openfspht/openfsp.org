The online demonstration lets you try an OpenFSP payment without a merchant account or real funds. The other commands on this page run the images published on GHCR; Docker is their only requirement.

To integrate a merchant application server, use the [Kotlin and Java SDK](https://github.com/openfspht/openfsp/tree/main/sdks/kotlin) (`org.openfsp:openfsp-sdk`) or the [TypeScript SDK](https://github.com/openfspht/openfsp/tree/main/sdks/typescript) (`@openfsp/sdk`). These packages are published on Maven Central and npm. Set `OPENFSP_BASE_URL` and `OPENFSP_API_KEY`, and keep the key exclusively on the server.

To expose the provider-side API, follow the [implementation guide](/en/docs/native-operator).

## 1. Online demonstration

| Service | Address |
| --- | --- |
| Shop | [demo.openfsp.org](https://demo.openfsp.org) |
| OpenFSP server | `https://gateway.openfsp.org` |
| Console | [console.openfsp.org](https://console.openfsp.org) |
| Mock server | [simulator.openfsp.org](https://simulator.openfsp.org) |
| Validator | [validator.openfsp.org](https://validator.openfsp.org) |

The OpenFSP server is the [gateway](/en/docs/gateway), connected to the simulator’s payment services. The console opens with the admin token `demo-admin-token`, and the demonstration API key `ofsp_test_DemoShopKeyPublishedForTheSimulator01` is public. Data in this environment is shared and may be erased.

### First simulated payment

1. Open the [shop](https://demo.openfsp.org).
2. Add a product to the cart and select a service marked “(mock)”.
3. Follow the simulated flow, with no merchant account or real funds.
4. Sign in to the [console](https://console.openfsp.org) with `demo-admin-token`, then open the payment. The success scenario produces the transition from `pending` to `succeeded`.

## 2. Images

The mock server runs without configuration:

```bash
docker run --rm -p 8090:8090 ghcr.io/openfspht/simulator:0.5.0
```

Its interface is served on `http://localhost:8090` and the reference server on `http://localhost:8090/mock_openfsp`. The gateway requires PostgreSQL and an application key; its [deployment](/en/docs/gateway) describes its configuration.

## 3. Conformance of an implementation

```bash
curl -fsSLO https://cdn.openfsp.org/validate.sh && sh validate.sh https://operator.example
```

The suite assesses an implementation from its address alone: it asks for its test keys and its control interface ([conformance 4.8](/en/docs/spec/conformance#4.8) and [4.9](/en/docs/spec/conformance#4.9)). The [implementation guide](/en/docs/native-operator) describes the options and how to read the report.
