La commande `make demo` démarre un environnement permettant d’expérimenter un paiement OpenFSP sans compte marchand ni mouvement de fonds réels. Exécutez les commandes suivantes depuis la racine du dépôt [`openfsp`](https://github.com/openfspht/openfsp).

Pour intégrer le serveur d’une application marchande, utilisez le [SDK Kotlin et Java](https://github.com/openfspht/openfsp/tree/main/sdks/kotlin) (`org.openfsp:openfsp-sdk`) ou le [SDK TypeScript](https://github.com/openfspht/openfsp/tree/main/sdks/typescript) (`@openfsp/sdk`). Ces paquets sont publiés sur Maven Central et npm. Renseignez `OPENFSP_BASE_URL` et `OPENFSP_API_KEY`, et conservez la clé exclusivement côté serveur.

Pour exposer l’API côté fournisseur, suivez le [guide d’implémentation](/docs/native-operator). Le [validateur public](https://validator.openfsp.org) permet également d’évaluer les exigences prises en charge par la suite.

## 1. Démonstration avec Docker

Prérequis : Git, Make et Docker avec le plugin Compose. Vérifiez ce dernier avec `docker compose version`. Au premier lancement, le téléchargement des images et la compilation des services nécessitent une connexion Internet et peuvent prendre plusieurs minutes.

```bash
git clone https://github.com/openfspht/openfsp.git
cd openfsp
make demo
```

Au premier lancement, cette cible crée le fichier `.env` qui contient la clé `OPENFSP_APP_KEY`, comme `make keys`. Elle exécute ensuite `docker compose --profile demo up --build`, qui exige ce fichier, et démarre les services suivants :

| Service                     | Adresse                 |
| --------------------------- | ----------------------- |
| Serveur OpenFSP             | `http://localhost:8080` |
| Console                     | `http://localhost:5173` |
| Interface du serveur simulé | `http://localhost:5175` |
| Interface du validateur     | `http://localhost:5176` |
| Boutique                    | `http://localhost:3000` |

Le simulateur est également accessible sur `127.0.0.1:8090`. PostgreSQL n’a pas de port hôte fixe, et le service de validation n’est joignable que par son interface. Pour accéder à la console, utilisez le jeton d’administration `demo-admin-token`. La découverte des points d’accès est disponible à `/.well-known/openfsp-configuration`. Le serveur sur le port 8080 correspond à la [passerelle](/docs/gateway), connectée aux services de paiement du simulateur.

### Premier paiement simulé

1. Attendez le démarrage des services, puis ouvrez la [boutique locale](http://localhost:3000).
2. Ajoutez un produit au panier et sélectionnez un service portant la mention « (mock) ».
3. Suivez les étapes du parcours simulé, sans compte marchand ni fonds réels.
4. Accédez à la [console locale](http://localhost:5173) avec `demo-admin-token`, puis consultez le paiement. Le scénario de réussite produit la transition de `pending` vers `succeeded`.

L’environnement Docker et le mode développement décrit ci-dessous utilisent les mêmes ports : arrêtez l’un avant de démarrer l’autre.

Pour arrêter la démonstration, appuyez sur Ctrl+C, puis exécutez :

```bash
docker compose --profile demo down
```

Les données PostgreSQL restent dans un volume nommé après `down` ; `docker compose --profile demo down -v` les supprime. En cas d’échec au démarrage, consultez les journaux avec `docker compose --profile demo logs --tail=100`. Si un port requis est occupé, libérez-le avant de relancer `make demo`. Vérifiez également que Docker fonctionne et que les images sont accessibles.

## 2. Développement

L’environnement de développement nécessite le JDK 25, Bun et une instance PostgreSQL accessible sur `127.0.0.1:5432`. Par défaut, le rôle `openfsp`, de mot de passe `openfsp`, est propriétaire de la base `openfsp`. Les variables `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME` et `SPRING_DATASOURCE_PASSWORD` permettent d’adapter cette configuration.

```bash
make install
make dev
```

`make dev` ouvre un terminal avec un processus par onglet et authentifie la console avec `demo-admin-token`. L’application marchande de démonstration se trouve dans le dépôt [openfspht/demo](https://github.com/openfspht/demo). Exécutez-la en parallèle avec la clé d’API de démonstration.

| Processus                   | Port                |
| --------------------------- | ------------------- |
| Serveur OpenFSP             | 8080                |
| Serveur simulé              | 8090                |
| Validateur                  | 8095                |
| Console                     | 5173                |
| Interface du serveur simulé | 5175                |
| Interface du validateur     | 5176                |

`make check` exécute la compilation, les analyses statiques, la vérification des types et les tests des composants serveur et des interfaces clientes.

## 3. Conformité d'une implémentation

`make validate TARGET=<adresse>` évalue une implémentation à partir de sa seule adresse : la suite lui demande ses clés de test et son interface de contrôle ([conformité 4.8](/docs/spec/conformance#4.8) et [4.9](/docs/spec/conformance#4.9)). Le [guide d’implémentation](/docs/native-operator) décrit l’exécution contre le serveur simulé de référence et la lecture du rapport.
