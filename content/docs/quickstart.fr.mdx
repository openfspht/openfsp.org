---
title: Démarrage rapide
description: Installer un SDK marchand, simuler un paiement en local et tester la conformité.
---

Testez un paiement OpenFSP sans compte marchand ni argent réel avec `make demo`. Les commandes ci-dessous se lancent à la racine du dépôt [`openfsp`](https://github.com/openfspht/openfsp).

Pour intégrer votre serveur marchand, utilisez le [SDK Kotlin et Java](https://github.com/openfspht/openfsp/tree/main/sdks/kotlin) (`org.openfsp:openfsp-sdk`) ou le [SDK TypeScript](https://github.com/openfspht/openfsp/tree/main/sdks/typescript) (`@openfsp/sdk`) ; tous deux arrivent sur Maven Central et npm avec la version `0.1.0`. Configurez `OPENFSP_BASE_URL` et `OPENFSP_API_KEY`. Gardez cette clé côté serveur.

Pour implémenter l’API, suivez le [guide d'implémentation](/fr/docs/native-operator). Le [validateur public](https://validate.openfsp.org) est aussi disponible.

## 1. Démonstration avec Docker

Il faut Git, Make et Docker avec le plugin Compose (`docker compose version`). Le premier lancement télécharge les images et compile les services ; prévoyez plusieurs minutes et une connexion Internet.

```bash
git clone https://github.com/openfspht/openfsp.git
cd openfsp
make demo
```

La cible lance `docker compose --profile demo up --build` et démarre :

| Service                     | Adresse                 |
| --------------------------- | ----------------------- |
| Serveur OpenFSP             | `http://localhost:8080` |
| Console                     | `http://localhost:5173` |
| Interface du serveur simulé | `http://localhost:5175` |
| Interface du validateur     | `http://localhost:5176` |
| Boutique                    | `http://localhost:3000` |

Le simulateur écoute aussi sur `127.0.0.1:8090`. PostgreSQL et le service de validation tournent sans port hôte fixe. La console demande le jeton d'administration :
`demo-admin-token`. Les clients découvrent les points d'accès sur `/.well-known/openfsp-configuration`. Le serveur du port 8080 est la [passerelle](/fr/docs/gateway), placée devant les opérateurs du simulateur.

### Premier paiement simulé

1. Attendez que les services soient prêts, puis ouvrez la [boutique locale](http://localhost:3000).
2. Ajoutez un produit au panier et choisissez un opérateur portant la mention « (mock) ».
3. Suivez le parcours proposé par le simulateur. Aucun compte marchand ni argent réel n'est nécessaire.
4. Ouvrez la [console locale](http://localhost:5173) avec `demo-admin-token` et retrouvez le paiement. Dans le scénario de succès, son état passe de `pending` à `succeeded`.

Les ports de cette démo Docker diffèrent de ceux du mode développement ci-dessous.

Pour arrêter la démo, utilisez Ctrl+C, puis :

```bash
docker compose --profile demo down
```

Cette commande conserve les volumes de données. Si un service ne démarre pas, consultez `docker compose --profile demo logs --tail=100`. Si un port est occupé, arrêtez le processus qui l'utilise avant de relancer `make demo`. Vérifiez que Docker est lancé et que les images peuvent être téléchargées.

## 2. Développement

Il faut le JDK 25, Bun et un PostgreSQL sur `127.0.0.1:5432`, avec un rôle `openfsp` propriétaire d'une base `openfsp`. `DB_NAME`, `DB_USER` et `DB_PASSWORD`
permettent de les changer.

```bash
make install
make dev
```

`make dev` ouvre un terminal à onglets, un processus par onglet, et connecte la console avec `demo-admin-token`. La boutique de démonstration a son propre dépôt, [openfspht/demo](https://github.com/openfspht/demo) ; lancez-la à côté de `make dev` avec la clé d'API de démonstration.

| Processus                   | Port                |
| --------------------------- | ------------------- |
| Serveur OpenFSP             | 8080                |
| Serveur simulé              | 8090                |
| Validateur                  | 8095                |
| Console                     | 5173                |
| Interface du serveur simulé | 5175                |
| Interface du validateur     | 5176                |

`make check` compile, analyse, vérifie les types et teste le backend et le frontend.

## 3. Conformité d'une implémentation

```bash
make simulator         # terminal 1
make validate-native   # terminal 2
```

`make validate-native` exécute la suite avec la cible `server` contre `mock_openfsp`, le serveur simulé de référence, sur
`http://127.0.0.1:8090/mock_openfsp` (`VALIDATE_NATIVE_BASE_URL`), avec les clés qu'il publie. Le rapport est écrit dans
`backend/validator/infrastructure/build/conformance-report-native.json`.

Le [guide d'implémentation](/fr/docs/native-operator) explique comment lire le rapport.
