The normative rules of OpenFSP. The [decisions](/docs/decisions) explain why each one exists.

## Scope of terms

The standard defines the shared contract independently of the reference gateway. A native provider exposes that contract itself; a client library can connect to it directly. Where a rule names the gateway, it describes that target's responsibilities. Requirements applicable to a native provider are specified by [conformance](/docs/spec/conformance#5.7). Translation into existing APIs is documented on the [gateway page](/docs/gateway).

## Keywords

MUST, MUST NOT, SHOULD, SHOULD NOT, MAY, REQUIRED, RECOMMENDED and OPTIONAL are read as in RFC 2119 and RFC 8174 when written in capitals.

Each rule has a number. Link to it with its anchor, for example [`/docs/spec/idempotency#3.2`](/docs/spec/idempotency#3.2).

## Implementation path

The [native provider guide](/docs/native-operator) connects chapters to implementation tasks and tests. The [project status](/docs/status) gives the state of each component. These guides are informative; numbered obligations are authoritative.

## Vocabulary

| Term       | Meaning                                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------------ |
| provider   | Payment service implementing OpenFSP or reached through an adapter, such as MonCash or NatCash. Called FSP in BRH circulars.                   |
| gateway    | Implementation of OpenFSP that receives client requests. It serves one merchant, who owns all its resources. |
| operator   | Whoever deploys and runs a gateway.                                                                          |
| client     | Application that calls an OpenFSP API.                                                                          |
| subscriber | Endpoint that receives OpenFSP events.                                                                 |
| verifier   | Party that checks an event signature: subscriber, auditor or library.                                        |
| principal  | Authenticated identity of a client.                                                                          |
