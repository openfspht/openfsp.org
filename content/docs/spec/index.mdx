The normative rules of OpenFSP. The [decisions](/docs/decisions) explain why each one exists.

## Scope of terms

The rules bind a server, which implements the API, and a client, which calls it. They do not say how a server is built or which systems it relies on.

## Keywords

MUST, MUST NOT, SHOULD, SHOULD NOT, MAY, REQUIRED, RECOMMENDED and OPTIONAL are read as in RFC 2119 and RFC 8174 when written in capitals.

Each rule has a number. Link to it with its anchor, for example [`/docs/spec/idempotency#3.2`](/docs/spec/idempotency#3.2).

## Implementation path

The [implementation guide](/docs/native-operator) connects chapters to implementation tasks and tests. The [project status](/docs/status) gives the state of each component. These guides are informative; numbered obligations are authoritative.

## Vocabulary

| Term             | Meaning                                                                                                   |
| ---------------- | --------------------------------------------------------------------------------------------------------- |
| provider         | Payment service identified in the [registry](/docs/registry), such as MonCash or NatCash. Called FSP in BRH circulars. |
| server           | Implementation of the OpenFSP API. It serves one or more providers.                                       |
| merchant account | The resources, principals and webhook endpoints of one merchant on a server. A server may hold several.   |
| operator         | Whoever deploys and runs a server.                                                                        |
| client           | Application that calls an OpenFSP API.                                                                    |
| subscriber       | Endpoint that receives OpenFSP events.                                                                    |
| verifier         | Party that checks an event signature: subscriber, auditor or library.                                     |
| principal        | Authenticated identity of a client. It belongs to one merchant account.                                   |
